# OLED 表示機能の構想メモ

スピーカーで曲を流すのに加えて、OLED（SSD1306、128×64、白黒）で感情推定の結果を「見せる」機能を追加する構想。
採用候補は下の1〜4。状態: **構想段階（未実装）**。

5感情（Calm / Tense / Restless / Groove / Active）の判定を前提にするため、実装は判定ロジックが固まってから。
ただし絵やアニメーションの設計は実機データなしでも先に進められる。

## 採用候補

### 1. 感情キャラクター（中心機能）

画面に小さなキャラクターが住んでいて、判定した感情で表情・動きが変わる。

| 感情 | キャラの様子（案） |
|---|---|
| Calm | 眠っている、ゆっくり呼吸 |
| Tense | 汗をかく、震える |
| Restless | きょろきょろ、そわそわ動く |
| Groove | 踊る。腕のリズムの周期（0.5〜3Hz）に合わせて動く |
| Active | 走る |

- 装置が何を感じ取ったかが一目で伝わり、装置の「顔」になる
- 判定が外れたときに画面ですぐ気づけるので、判定ロジックの調整にも役立つ
- キャラクターはオリジナルのデザインにする

### 2. 呼吸ガイド（バイオフィードバック）

Tense がしばらく続いたら、画面を呼吸ガイドに切り替える。

- 円が4秒で膨らみ（吸う）、6秒で縮む（吐く）。秒数は調整値にする
- 数サイクル後、開始時からの心拍の変化を表示（例: `-8 bpm`）
- 同時に Calm フォルダの曲を流すのもあり
- 「感情を推定する」装置から「状態に寄り添う」装置へ一段上がる

### 3. 鼓動の表示

- 拍を検出するたびにハートのアイコンが脈打つ（1 のキャラの横に置く形で組み込める）
- 余裕があれば、心拍センサーの波形を心電図のように流す表示も

### 4. 気分の記録グラフ

- 10秒ごとの感情を1列ずつ並べた帯グラフ。128列 ≒ 約21分ぶん
- 「この20分は Groove が多かった」と振り返れる
- 記録は1判定1バイトで128バイト（3ビットに詰めれば48バイト）

## 技術メモ

### 描画方法

今は文字専用モード（U8x8）で、RAM 節約のためフルバッファの U8g2 は使わない方針。

| 方法 | 追加 RAM | 向いているもの |
|---|---|---|
| U8x8 のタイル描画（`drawTile` で 8×8 ドットの自作ビットマップを並べる） | ほぼ 0 | キャラ、ハート、帯グラフ |
| U8g2 ページバッファ（`_1` 系コンストラクタ、128バイト） | 約 128B | 円（呼吸ガイド）、波形、自由な図形 |

- 現在の main は RAM 58%（1202B）。ページバッファでも入る見込みだが、5感情の判定を入れた後の使用量次第
- ビットマップは `PROGMEM` に置いて RAM を使わない
- ページバッファは毎回全画面を描き直すので、描画時間が `readHeart()` の呼び出し間隔を空けすぎないよう注意（拍の取りこぼし）

### 画面の切り替え

- ボタンが無いので、加速度センサーのジェスチャー（手首を2回振る、傾けるなど）で画面を切り替える
- 例: キャラ画面 ⇔ 記録グラフ画面 ⇔ 数値画面（HR・動き）
- 呼吸ガイドは Tense で自動的に表示、ジェスチャーで中断

## LED・ボタンの活用

手元に未使用の LED とボタンが複数ある。上の機能と組み合わせて使う。
（個数・色・種類は未確認。RGB LED があるかで「感情の色」の作り方が変わる）

### ボタンの使い道

| 使い道 | 内容 |
|---|---|
| 画面切り替え | ジェスチャーより確実。キャラ ⇔ 記録グラフ ⇔ 数値 |
| 曲の操作 | 次の曲へ（スキップ）、音量の上げ下げ |
| 呼吸ガイドを手動で開始 | Tense の自動判定を待たずに始められる |
| **自己申告ラベル** | 「今の気分」をボタンで記録する。logger に列を足せば、記録データに本人の申告が正解ラベルとして入り、判定ロジックの評価がしやすくなる。main でも「判定がずれている」と押した時刻をログに残せる |

- 配線は `INPUT_PULLUP` でピンと GND の間にボタンをつなぐだけ（抵抗不要）
- チャタリング対策はソフトで行う（20〜50ms 待って再確認）
- 長押し・2回押しで機能を増やせるので、ボタン2〜3個で足りる見込み

### LED の使い道

| 使い道 | 内容 |
|---|---|
| 鼓動の点滅 | 拍を検出するたびに一瞬光る。画面を見なくても分かる |
| 感情の色 | 感情ごとに光る LED や色を変える（RGB なら1個で5色） |
| 呼吸ガイド | PWM で明るさをゆっくり上下させ、画面と同期して呼吸のペースを示す |
| Groove のリズム | 検出した腕のリズムの周期で点滅 |
| 状態表示 | 指が外れている、SD カードの異常など |

- 普通の LED には 220〜330Ω の抵抗を直列に入れる
- 明るさを変える（PWM）なら D3・D5・D6・D9 を使う。D10・D11 は DFPlayer で使用中

### 使えるピン

| ピン | 状態 |
|---|---|
| D0・D1 | 使わない（USB 通信） |
| D10・D11 | DFPlayer（使用中） |
| A4・A5 | I2C（使用中） |
| D2・D3・D4 | 配線ガイドで「任意」（MAX30102 INT / MPU INT / DFPlayer BUSY）。現状未使用なので LED・ボタンに回してよい |
| D5〜D9・D12 | 空き |
| D13 | 空き（基板上の LED とつながっている） |
| A0〜A3 | 空き。ただし main は乱数の種に A0〜A3 のノイズを使っているので、ここに部品をつなぐなら `makeSeed()` を変える |

ピン割り当て案（LED・ボタンの個数が分かったら確定する）:

- ボタン: D2・D4・D7（D2 は割り込みも使える）
- LED: D3・D5・D6・D9（PWM で明るさを変えられる）

## 見送った案（参考）

- リズムゲーム（腕振りと曲のテンポのシンクロ率）: DFPlayer は曲の情報を読めず、曲ごとのテンポをコードに登録する必要がある
- 傾き操作のミニゲーム: 面白いが感情推定のテーマから外れる
